# G7 — how a Z / M value is written

**Question** (spec 093 § Experiments, G7): the write path builds `STGeomFromWKB(lit, srid)` (D6). Does
the server take a value's Z and M that way, or in WKT? Which form?

**Method** (2026-11-20, SQL Server 2022 16.0, a throwaway container of `test/backup/gen/images.txt`'s
image; literals only, no table). Each form was passed to `geometry::` / `geography::STGeomFromWKB` or
`STGeomFromText`, and the result read back by `AsTextZM()`.

**Result.**

| input | form | result |
|---|---|---|
| `STGeomFromWKB`, ISO type 1001 (Z) | `01 E9030000 x y z` | `POINT (1 2 3)` |
| `STGeomFromWKB`, ISO 2001 (M) | `01 D1070000 x y m` | `POINT (1 2 NULL 4)` |
| `STGeomFromWKB`, ISO 3001 (ZM) | `01 B90B0000 x y z m` | `POINT (1 2 3 4)` |
| `geography::STGeomFromWKB`, ISO 1001, 4326 | longitude first | `POINT (10 50 100)` |
| `STGeomFromWKB`, EWKB Z flag (0x80000001) | | refused: 24115, "The well-known binary (WKB) input is not valid" |
| `STGeomFromText('POINT(1 2 3 4)')` | | `POINT (1 2 3 4)`, stored as G1's ZM form |
| `STGeomFromText('LINESTRING(0 0 NULL 5, 1 1 NULL 6)')` | | M without Z |
| `STGeomFromText('POINT ZM (1 2 3 4)')`, `'POINT M (1 2 4)'` | ISO WKT tags | refused: 24142, `Expected "(" … The input has "Z"` |
| `STGeomFromWKB`, a point of two NaN (DuckDB's POINT EMPTY, K1) | | refused: 24126, "Point coordinates cannot be infinite or not a number (NaN)" |
| `STGeomFromWKB`, MULTIPOINT EMPTY (`010400000000000000`) | | `MULTIPOINT EMPTY` |
| `CAST(0x<MS-SSCLRT> AS geometry)` | G1's stored ZM point | `POINT (1 2 3 4)` |

## What it means for T6 (D6)

- **Z / M are written as ISO WKB through `STGeomFromWKB`.** The writer sends DuckDB's WKB as it is:
  it is ISO, and K1 measured DuckDB taking and giving ISO Z / M / ZM. D6's fallback is not needed:
  no Z / M value is refused for want of a form.
- **The stage takes the same call.** The `INSERT … SELECT STGeomFromWKB(w, srid) FROM #stage` keeps
  Z / M too.
- **A POINT EMPTY must be rewritten.** DuckDB's form is a point of NaN coordinates (K1), and the
  server refuses NaN. The writer sends `STGeomFromText('POINT EMPTY', srid)`, which stores a POINT
  EMPTY and reads back as one (G1's form). MULTIPOINT EMPTY's WKB, which the server takes too, is no
  substitute: it stores a MULTIPOINT EMPTY, a value of another type, and the read keeps the two apart
  (a POINT EMPTY is read as the value as stored: owner, 2026-11-20, spec § T5). The literal path and the
  stage both need it. Recorded in D6.
- **`geometry_as 'native'` values load back by `CAST(… AS geometry)`,** the stored bytes taken as
  they are. That is D6's statement, now measured.
- **G4** (INSERT BULK of client-built MS-SSCLRT) is still to measure, with T6's code.
