# G1 and G3 — `geometry` / `geography` as stored, against the server's WKB

**Question** (spec 093 § Experiments, G1 and G3).
- What does a `geometry` / `geography` value hold, in MS-SSCLRT, for every OGC type? That covers
  EMPTY, holes, collections, Z / M / ZM, the curves and FullGlobe.
- Can a decoder of those bytes give `AsBinaryZM()` byte for byte, and `STAsBinary()` without Z / M?
- Which coordinate comes first in a `geography` value (G3)?

**Method** (2026-11-20, throwaway containers of the images in `test/backup/gen/images.txt`: SQL
Server 2019, 2022 and 2025; synthetic values only; the raw output is kept out of the repository).
- **Values.** 65 values, each `STGeomFromText` of its WKT. 46 are `geometry`, in SRID 0 or 3857. 19
  are `geography`, in SRID 4326, 4269 or 104001, plus `geography::Point(50, 10, 4326)`.
- **Columns read per value.**
  - `CAST(g AS varbinary(max))`: the stored form, the bytes a bare UDT read carries (G2);
  - `STAsBinary()`, `AsBinaryZM()` and `AsTextZM()`;
  - `STSrid` and `STGeometryType()`.
- **Decoder.** A prototype (Python, kept out of the repository) put each stored value into WKB. It
  was compared with both WKB methods.

**Result.**
- **The decoder matches.** On every version it gave the server's bytes in 128 of 128 comparisons:
  each value's `AsBinaryZM()` and `STAsBinary()`, curves and FullGlobe included.
- **The versions agree.** 2019, 2022 and 2025 answered every value with the same bytes, for all
  five forms.
- SQL Server 2017 does not start on this machine (its image crashes under Rosetta). Its lane is the
  oracle's, once T8 adds a fixture per type.

## The stored form

The layout is MS-SSCLRT 2.1, as the specification gives it:
- **Header.** u32 SRID, u8 version, u8 properties.
  - Version 1 is used when the value needs nothing of version 2, version 2 otherwise.
  - Properties: Z 0x01, M 0x02, V(alid) 0x04, P (a single point) 0x08, L (a single line of two points)
    0x10, H (larger than a hemisphere) 0x20.
- **P or L.** The header is followed by the point (or the two points), then their Z values, then
  their M values.
- **Otherwise.** u32 point count; the points as (x, y) pairs; every Z, then every M.
- **Figures.** u32 count, then per figure: u8 attribute, u32 first point.
- **Shapes.** u32 count, then per shape: i32 parent, i32 first figure (−1: EMPTY), u8 OGC type.
- **Segments** (version 2, when the value has them): u32 count, then one byte per segment.

Measured details:

- **Version 2 is written for:**
  - a curve (shape types 8 CircularString, 9 CompoundCurve, 10 CurvePolygon);
  - FullGlobe (shape type 11);
  - a `geography` polygon larger than a hemisphere, with H set: `POLYGON((0 0, 0 10, 10 10, 10 0,
    0 0))` in 4326 has properties 0x24.
- **Figure attributes.**
  - Version 1: 0 interior ring, 1 stroke, 2 exterior ring.
  - Version 2: 1 line, 2 arc, 3 composite curve. The hemisphere polygon's ring is attribute 1.
- **Segments of a CompoundCurve.**
  - 2 and 3 start a line and an arc.
  - 0 and 1 continue one.
  - Each part starts at the previous one's last point.
- **EMPTY.** An EMPTY value of any type is a header with properties V (0x04), then:
  - 0 points and 0 figures;
  - one shape with parent −1, figure −1 and its OGC type.
- **An EMPTY member of a collection** is a shape with figure −1 (`MULTIPOINT((1 2), EMPTY)`).
- **A missing Z / M** in a value that has the other (`LINESTRING(0 0 1, 1 1 NULL)`) is stored as
  the NaN `0xFFF8000000000000`.
- **An invalid instance** keeps V clear (properties 0x00) and is stored as given (a self-crossing
  polygon from `STGeomFromText`). `STAsBinary()` / `AsBinaryZM()` take it.
- **SRID** is kept as given: 4269 is `AD100000`, 104001 too.

## G3: the coordinate order

A `geography` value stores **latitude first**. `geography::Point(50, 10, 4326)` and
`STGeomFromText('POINT(10 50)', 4326)` both store `E6100000 01 0C 0000000000004940
0000000000002440`: SRID 4326, version 1, V | P, then 50 and 10. Its WKB, as both methods give it, is
longitude first: `0101000000 0000000000002440 0000000000004940`. G2 found the same bytes on the wire.
A `geometry` value stores (x, y) as given.

## The WKB the server gives

- **Z / M type codes.** `AsBinaryZM()` writes ISO WKB: the type code plus 1000 (Z), 2000 (M) or 3000
  (ZM). Each point's coordinates are x, y, z, m. `STAsBinary()` drops Z and M.
- **A missing coordinate is NaN `0x7FF8000000000000`.** The stored `0xFFF8…` is put in that
  canonical form.
- **POINT EMPTY is written as MULTIPOINT EMPTY:** `010400000000000000`, type 4 with 0 members, from
  both methods. `GEOMETRYCOLLECTION(POINT EMPTY, POINT(1 2))` holds it the same way. An EMPTY member
  of a MULTIPOINT is left out (`MULTIPOINT((1 2), EMPTY)` is a MULTIPOINT of one point). The other
  EMPTY types keep their type with 0 members.
- **The curves are ISO WKB:** 8 CircularString, 9 CompoundCurve (its parts as LineString /
  CircularString), 10 CurvePolygon (each ring by its figure's attribute).
- **FullGlobe** is `017E000000`, type 126, which is no OGC type.
- **The server refuses some values at insert:**
  - a circular arc whose three points have different Z (24214);
  - FullGlobe inside a collection (24150).

## What it means for T5 (D6)

- **The kernel's mapping is the prototype's.**
  - The point arrays, then the figures cut by the next figure's first point.
  - Shapes become nested WKB by their parents.
  - For `geography`, the stored latitude and longitude are swapped.
  - NaN is put in its canonical form.
- **Curves and FullGlobe cannot be a `GEOMETRY`.** DuckDB's WKB reader refuses the ISO curve codes and
  126 (K1). Under `geometry_as 'geometry'` they are NULL with a WARNING (owner, 2026-11-20); `'wkb'`
  keeps them as the WKB above, `'native'` as the stored bytes.
- **POINT EMPTY is the one place where `AsBinaryZM()` loses information.** It changes the type to
  MULTIPOINT. DuckDB's `GEOMETRY` holds a POINT EMPTY as a point of NaN coordinates (K1). The kernel
  gives POINT EMPTY, the value as stored (owner, 2026-11-20): there, and only there, it is not
  `AsBinaryZM()` byte for byte.
- **Validity is not checked.** An invalid instance (V clear) is read as stored, as `STAsBinary()`
  reads it.
