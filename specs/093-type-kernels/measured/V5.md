# V5 — `sys.columns` and `sys.types` for vector columns

**Question** (spec 093 § Experiments, V5): how does a catalog query on 2025 learn that a column is a
vector, its dimensions and its element type?

**Method** (2026-11-13, SQL Server 2025 17.0.5035.5, throwaway containers). The raw output is kept
out of the repository. The query read `sys.columns` for V1's tables, with `TYPE_NAME` of both type ids
and the 2025 columns `vector_dimensions` and `vector_base_type_desc`, and it read `sys.types`.

**Result.**

- **`sys.columns`.**

  | column | system_type_id | user_type_id | TYPE_NAME(system) | TYPE_NAME(user) | max_length | precision | scale | vector_dimensions | vector_base_type_desc |
  |---|---|---|---|---|---|---|---|---|---|
  | `vector(3)` | 165 | 255 | varbinary | vector | 20 | 0 | 0 | 3 | float32 |
  | `vector(3, float16)` | 165 | 255 | varbinary | vector | 14 | 0 | 1 | 3 | float16 |
  | `vector(1998)` | 165 | 255 | varbinary | vector | 8000 | 0 | 0 | 1998 | float32 |

  - The two 2025 columns exist and answer directly.
  - `scale` carries the same element type (0 / 1), as in the backup (V4).
  - `max_length` is `8 + n × element size`.
- **`sys.types`.** The `vector` row has system_type_id 165, user_type_id 255, max_length 8000,
  `is_user_defined` 0, and schema `sys`.
- **Alias types.** `CREATE TYPE dbo.Emb FROM vector(3)` is refused: Msg 42212, "Cannot create alias
  types from a vector datatype". This was measured in a second run on the same image. A vector
  cannot hide behind an alias type.

**For D4.**
- The metadata queries detect a vector by `user_type_id = 255`.
- They take the element type from `scale` and n from `(max_length - 8) / (scale = 1 ? 2 : 4)`.
- The 2025 columns `vector_dimensions` / `vector_base_type_desc` are not named, because the same
  query text must compile on 2017–2022, where they are invalid column names.
