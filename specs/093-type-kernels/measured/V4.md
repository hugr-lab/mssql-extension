# V4 — `vector` in a backup

**Question** (spec 093 § Experiments, V4): how is a vector column described in a backup's
`syscolpars`, and how are its values stored? This settles the backup's vector detection for T8 and
the element-type field: a u32, or a u8 followed by reserved bytes.

**Method** (2026-11-13). The backup is a full backup of V1's database (`vector(3)`,
`vector(3, float16)`, `vector(1998)`), taken on SQL Server 2025 17.0.5035.5 in a throwaway container.
It is not committed (only synthetic fixtures are; T8 adds a vector fixture to the generator). The
reader at spec 085 PR 3 (`feat/085-lob`) read it through `mssql_backup_columns`,
`mssql_backup_catalog(…, 'syscolpars')` and `mssql_backup_scan`.

**Result.**

- **syscolpars.**

  | column | xtype | utype | length | scale |
  |---|---|---|---|---|
  | `vector(3)` | 165 | 255 | 20 | 0 |
  | `vector(3, float16)` | 165 | 255 | 14 | 1 |
  | `vector(1998)` | 165 | 255 | 8000 | 0 |

  - xtype is `varbinary` and utype is 255, the `vector` row of `sysscalartypes`.
  - `scale` is the element type.
  - `length` is `8 + n × element size`.
- **Stored value.** The bytes are those the wire sends under VECTORSUPPORT (V1), unchanged.
  - Bytes 0–1 are `A9 01`, bytes 2–3 the dimensions as a u16, byte 4 the element type
    (0 = float32, 1 = float16), and bytes 5–7 are zero.
  - The elements follow, little-endian. For example, `vector(3, float16)` `[1,2,3]` is stored as
    `a9 01 0300 01 000000 003c 0040 0042`, and `vector(1998)` begins `a9 01 ce07 00 …`.
  - The element type is a u8 followed by reserved bytes, not a u32.
  - A NULL value (`vt` row 4, `vt16` row 3) is read as NULL. It has no header.
- **The reader today.**
  - `mssql_backup_columns` reports `sql_type` `vector` correctly. It reports `system_type`
    `varbinary(20)`, `duckdb_type` `BLOB` and `state` `converted`.
  - The scan returns the 20 / 14 / 8000 stored bytes. The values are exact, but they are not yet
    a `FLOAT[n]`.
  - This is the recon's finding, now measured: the type is taken from xtype, so the reader's
    vector test never fires.

**For T8.** A column with xtype 165 and utype 255 is `vector`. Its n is `(length - 8) / (scale ? 2 :
4)`, and its kernel is D1's vector kernel over the stored bytes, the same bytes as the `0xF5` wire
value. No conversion beyond the kernel is needed.
