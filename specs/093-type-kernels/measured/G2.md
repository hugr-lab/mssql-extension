# G2 — UDT and SSVARIANT columns on the wire

**Question** (spec 093 § Experiments, G2): how does SQL Server send a `geometry`, `geography`,
`hierarchyid` and `sql_variant` column that is selected bare? What does COLMETADATA's TYPE_INFO hold,
what is MAX_BYTE_SIZE for each CLR type, and is a small UDT (`hierarchyid`, 892 bytes at most)
PLP-framed?

**Method** (2026-11-13, SQL Server 2022 16.0.4305.5, a throwaway container, not committed). Table
`dbo.t (id int, g geometry, gg geography, h hierarchyid, v sql_variant)`, five rows: a point, a
LINESTRING with Z in SRID 3857, a polygon, NULLs, the root and `/1.5/-2/`, and `sql_variant` values of
base type int, nvarchar(10), decimal(9,3) and datetime. An ad hoc client on the extension's own
`TdsConnection` sent `SELECT id, <column> FROM dbo.t ORDER BY id` for each column and printed the raw
response. A decoder walked COLMETADATA and the rows, and compared each UDT value with the server's
`CAST(<column> AS varbinary(max))`.

**Result.** Every UDT value equals the server's varbinary bytes (15 of 15, NULLs included).

- **UDT (0xF0) TYPE_INFO**, as MS-TDS 2.2.5.5.2 gives it:
  - u16 MAX_BYTE_SIZE: 0xFFFF for `geometry` and `geography`, 892 for `hierarchyid`;
  - DB_NAME, SCHEMA_NAME and TYPE_NAME as B_VARCHAR: `g2`, `sys`, `geometry` / `geography` /
    `hierarchyid`. The system CLR types have schema `sys`;
  - ASSEMBLY_QUALIFIED_NAME as US_VARCHAR, for example `Microsoft.SqlServer.Types.SqlGeometry,
    Microsoft.SqlServer.Types, Version=11.0.0.0, Culture=neutral, PublicKeyToken=89845dcd8080cc91`
    (132 characters).
- **UDT values are always PLP**: a u64 total length, then chunks and a 0 terminator. This holds for
  `hierarchyid` too, whose MAX_BYTE_SIZE is 892, not 0xFFFF. NULL is the PLP NULL, or a bit of an
  NBCROW. The root `hierarchyid` is a non-NULL value of 0 bytes.
- **The bytes are the stored MS-SSCLRT form**: `geography::Point(50, 10, 4326)` is
  `E6100000 01 0C 0000000000004940 0000000000002440`. That is SRID 4326, version 1, properties V | P
  (a single point), then latitude 50 and longitude 10: the latitude comes first on the wire as on
  disk (part of G3).
- **SSVARIANT (0x62)**: TYPE_INFO is a LONGLEN maximum of 8009. A value is a u32 length, then
  BASETYPE, PROPBYTES, the properties and the value in its TDS form:
  - int: `38 00 05000000`;
  - nvarchar(10): `E7 07`, a 5-byte collation `0904D00034`, u16 maximum length 20, then `abc` in
    UTF-16LE;
  - decimal(9,3): `6A 02 09 03`, then a sign byte and a **16-byte** mantissa (`01 39300000 00…`).
    That is not the 4 bytes a decimal(9) takes in a column. S1 checks it for other precisions;
  - datetime: `3D 00`, then the days (`01B50000`) first and the ticks after, as the column form.
- Rows holding a NULL come as NBCROW (0xD2): a null bitmap, then the non-NULL values only.

**Used by** T0 (the TYPE_INFO parse and PLP framing of 0xF0, and the LONGLEN framing of 0x62), T1
(the SSVARIANT envelope, the decimal mantissa width), T4 and T5 (UDT_INFO's type name, so a raw scan
can type a column without a catalog).
