# V2 — the `vector` JSON fallback (no VECTORSUPPORT)

**Question** (spec 093 § Experiments, V2): without the feature, the server sends a vector as text.
Is that text exact for float32 and float16?

**Method** (2026-11-13, SQL Server 2025 17.0.5035.5, throwaway containers). The raw output is kept
out of the repository.
- **Input.** `INSERT … VALUES (…, '[…]')` with the values below.
- **Reading.** The server's text was read by sqlcmd (`CAST(v AS nvarchar(max))`) and on the wire,
  by an ad hoc client with no feature negotiated that printed the raw response.
- **Reference.** The text was compared with the stored bits, which V4 read from a backup.

**Wire.** The column is `a7 ffff 0904002600`: varchar(max), PLP, `Latin1_General_100_BIN2_UTF8`,
UserType 255.
- A value is the PLP text `[e1,e2,…]`.
- Each element is printed `%.7e` with a three-digit exponent, `1.0000000e+000`, which is 8
  significant digits.

| input | stored bits (V4) | text |
|---|---|---|
| `1, 2, 3` | `3f800000 40000000 40400000` | `1.0000000e+000,2.0000000e+000,3.0000000e+000` |
| `0.1, -0.0, 3.4028235e38` | `3dcccccd 00000000 7f7fffff` | `1.0000000e-001,0.0000000e+000,3.4028235e+038` |
| `1e-45, -1.17549435e-38, 1.17549421e-38` | `00000001 80800000 007fffff` | `1.4012985e-045,-1.1754944e-038,1.1754942e-038` |
| `0.33333334, 16777217, -2.5` | `3eaaaaab 4b800000 c0200000` | `3.3333334e-001,1.6777216e+007,-2.5000000e+000` |
| float16 `0.1, -0.0, 65504` | `2e66 0000 7bff` | `9.9975586e-002,0.0000000e+000,6.5504000e+004` |

**Result.**

- **float32 is not exact.** Eight significant digits do not identify every float32.
  - **Off the server.** 2,000,000 random 32-bit patterns were drawn, and 1,992,138 of them were
    finite. Of those, 30,174 (1.5 %) have a `%.7e` text that does not parse back to the same float32.
    Such a value parses to a neighbour, one ulp (unit in the last place) away, by the 8-digit bound.
  - **On the server.** `-103.217316` (`c2ce6f44`) and `-103.217323`, its neighbour, both print as
    `-1.0321732e+002`.
  - **The round trip.** `VECTOR_DISTANCE('euclidean', v, CAST(CAST(v AS nvarchar(max)) AS vector(3)))`
    is 68719476736 for `[-103.217316, -1.16638425e-07, 1.00584066e+18]`. That is 2^36, the ulp of
    the 1e18 element. The server's own text does not round-trip.
- **float16.** The three values tried print exactly. 8 digits are more than float16 needs, so the text
  is exact for every float16 (derived).
- **-0.0.** It is stored as +0.0 (`00000000`), because the JSON input already loses the sign. The
  text adds no further loss.
- **Denormals and extremes.** Denormals are printed and stored as such. `16777217` is stored as
  16777216, which is the input's rounding.

**For D4.** About 1.5 % of float32 elements read through the fallback differ from the stored value
by one ulp. D4's one-line `WARNING` per catalog is needed. A float16 vector read through the fallback
is exact, and under version 1 a float16 vector always takes the fallback (V1).
