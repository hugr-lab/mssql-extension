# S2 — INSERT BULK into a `sql_variant` column

**Question** (spec 093 § Experiments, S2): does SQL Server take a `sql_variant` column on the bulk
wire -- `0x62` (SSVARIANT) in INSERT BULK's COLMETADATA, each row's value an envelope as a row
carries it (S1) -- and does it store the base type, its properties and the value? This decides T2's
COPY / INSERT BULK / `#stage` path for a `VARIANT`: an encoder, or a refusal by name.

**Method** (2026-11-13, SQL Server 2022 16.0.4305.5 and 2025 17.0.5035.5, throwaway containers, not
committed). `dbo.s2 (id int NOT NULL, v sql_variant NULL)`. An ad hoc client on the extension's
`TdsConnection` sent, for each case on its own connection, `INSERT BULK dbo.s2 ([id] int, [v]
sql_variant)`, then one BULK_LOAD message: COLMETADATA with `id` as INTN(4) and `v` as `0x62` with a
LONGLEN maximum of 8009 (flags nullable), one ROW (`v` a u32 length and the envelope, 0 = NULL), DONE.
The server's answer was read for an ERROR token; then `SQL_VARIANT_PROPERTY` (BaseType, Precision,
Scale, MaxLength, Collation) and the value's text (`CONVERT(…, 121)` for the date / time types) of
every stored row.

**Result.** Every case is taken, on 2022 and 2025 alike (identical output). The stored value has
the envelope's base type, precision, scale, maximum length and collation, and its value:

- strings keep their collation: a varchar under `Cyrillic_General_CI_AS` (1251) and under
  `Latin1_General_100_CI_AS_SC_UTF8` store as such, their bytes read in it;
- a decimal is taken with the 16-byte mantissa a row carries **and** with the column form's 4 bytes
  (both store decimal(9,2) -1234567.89);
- `datetime2(7)` 9999-12-31 23:59:59.9999999, `datetimeoffset(7)` with its +05:30, `time(7)` with
  its 100 ns digit, money, uniqueidentifier, varbinary, bit, float and a padded char(5) store exactly;
- a length of 0 stores NULL.

The envelopes are S1's (`measured/S1.md`) but for case 6 (the decimal's mantissa cut to 4 bytes).

**So T2 writes a `VARIANT` on the bulk wire too:** an SSVARIANT encoder (a value's base type and
envelope from its VARIANT tag, D3's write table) serves COPY, INSERT BULK, the `#stage` of a staged
UPDATE / DELETE and a staged MERGE's `#src` -- none of them has to refuse a `VARIANT`, and the
statement path's literal is needed only where it is the path anyway.

Also measured the same day: S1 on 2025 (17.0.5035.5) -- its 50 envelopes are byte for byte 2022's,
the 16-byte decimal mantissa included.

**Used by** T2 (the bulk encoder, the COLMETADATA form above).
