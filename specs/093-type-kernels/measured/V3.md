# V3 — the describe of a vector column

**Question** (spec 093 § Experiments, V3): what does `sp_describe_first_result_set` report for
`SELECT v`, with and without VECTORSUPPORT? D4 expected a mismatch to tolerate: a `varchar(max)`
describe beside a `0xF5` stream.

**Method** (2026-11-13, SQL Server 2025 17.0.5035.5, throwaway containers). The raw output is kept
out of the repository. Two forms were asked on V1's client, once with version 1 negotiated and once
with no feature, and decoded from the raw rows:
- `EXEC sp_describe_first_result_set N'SELECT id, v FROM dbo.vt'`, and the same for `dbo.vt16`;
- `sys.dm_exec_describe_first_result_set`, the same engine as a table.

sqlcmd, which negotiates no feature, gave the first row of the table below.

| session | column | system_type_id | user_type_id | system_type_name | max_length |
|---|---|---|---|---|---|
| no VECTORSUPPORT | `vector(3)` | 167 | NULL | `varchar(max)` | -1 |
| no VECTORSUPPORT | `vector(3, float16)` | | | `varchar(max)` | |
| VECTORSUPPORT 1 | `vector(3)` | 165 | 255 | `vector(3)` | 20 |
| VECTORSUPPORT 1 | `vector(3, float16)` | | | `varchar(max)` | |

The procedure and the DMV agree in every case. The empty cells were not decoded beyond the type name.

**Result.** The describe follows the session, and in every case it names the form that session
streams:
- `0xF5` with `vector(n)`;
- JSON with `varchar(max)`, for a float16 column under version 1 and for any vector without the
  feature.

A session's describe and its stream do not disagree.

**For D4.**
- **Raw scans.** A raw `mssql_scan` maps system_type_id 165 with user_type_id 255 to `FLOAT[n]`,
  with n from max_length.
- **When a mismatch remains.** It can only come from two sessions that negotiated differently. D4
  reads `mssql_vector_support` once per catalog at ATTACH, so the logins of one catalog ask alike. A
  failover to a server of another build can still differ. That case is the existing shape-check
  error, not a new tolerance.
